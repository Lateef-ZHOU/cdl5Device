# CDL5 UDP / DMA 采集边界

## 上下行

开始 1 秒：`43 44 4c 35 01 00 00 00`；停止：`43 44 4c 35 00 00 00 00`。Handle 拒绝其他长度、magic 和大于 13 的秒数。send 成功表示命令交给工作线程，配置/采集失败由工作线程日志报告，不伪造完整谱或额外 ACK。Bridge 不解析命令。

上行原样保留 FPGA 帧，不加 Bridge 头。32 字节帧头：word0 为 0x324c4443，word1 为 0x05040507，word2 为门数高16位/频点数低16位；其他帧头字段包含触发周期、累积/Profile/bin 起点、配置代数、帧号与诊断。Collector 只核对识别与形状，然后跳过帧头。

每条记录 32 字节：word0/1/2 是 ADC0/1/2 的 FP32；word3/4 为非活动通道；word5/6/7 为 gate/bin、帧号、版本及通道标志。Collector 忽略后三个 meta 字，不依赖其排序。使用 qFromLittleEndian<uint32> 读取位型，再 bit_cast<float>，最后转 double；不将原位型数值转换成浮点、不对未对齐地址强转 float 指针。

| FPGA | 原谱 | 帧长 | 1024 字节传输 |
|---|---|---|---|
| 4 kHz / P9 | 500×128×3 | 2,048,032 | 2000 个整块 +32 字节尾块 |
| 5 kHz / P8 | 450×128×3 | 1,843,232 | 1800 个整块 +32 字节尾块 |

第一整块只有 31 条数据记录，后续整块有 32 条。不能每个 UDP 包都去掉 32 字节。短 read/EINTR 在 Handle 内补满本次块后才交付，不能把一条记录拆成两个数据报。

## 工作线程和取消

- 资源打开仍为 O_RDONLY DMA、/dev/mem 寄存器映射、CAPS/CAPACITY 检查。打开本身不触发采集。
- 主线程只交入最新开始/取消请求或关闭通知；工作线程独占寄存器访问、START/WAIT_KEEP/RESET/read。互斥量与条件变量只用于这一个待办命令，不保存另一份帧。
- 开始前要求 FPGA STOPPED 且 BUSY=0。检查活动门数/频点、5 lane/3 ADC、帧长和驱动容量。保留活动周期、bin 起点、范围、功率位移和通道映射，仅修改累积次数，提交 CONFIG_APPLY 并等待代数变化，验证活动累积值和 JESD 就绪。
- DMA START 先于 ENABLE=3 单次触发。WAIT_KEEP 每次最多等 100 ms；EAGAIN/EINTR 保持传输，完成状态和长度检查后从偏移0分块读取。
- 取消时 ENABLE=0，保留接收以让 FPGA 正常完成当前帧/停稳，收到的数据不再上传。正常等待预算是累积秒数+3秒；若 FPGA 未能停止，则同步 DMA RESET 后用文档中的 ENABLE bit16 软复位并等待200ms。RESET 只取消 DMA，不能代替 FPGA 停止。软复位异常会记录日志，下一次仍必须通过停稳检查。
- 关闭唤醒相同待办入口，HandleCore 同步等待工作线程退出；资源清理由 DmaConnection 对称执行。无额外 QThread、析构标志、保存排空或 Bridge 分包。
- 这不是退出延迟承诺：正常帧边界取消可能等待当前累积结束；故障设备和系统调用的返回仍受驱动约束。当前外触发模式若未收到足够脉冲，也按超时失败处理，不自动切换激光器模式。

## 来源与待实测

对照本机两份 FPGA 交付的 PS_compiled_inputs/app/hardware_access.c、service_types.h 以及相同 c33_v2_serializer.v 和 c33_epoch.v。新代码只实现本型号的必要顺序，未搬入旧 HTTP 服务状态机。频率切换兼容基于这两份交付相同的寄存器/32字节格式，不承诺任意未来 FPGA 协议都无需适配。

单帧有序接收是用户选择的简化：UDP 丢失、重复、乱序和旧包迟到不是由一次性发送本身消除的；本实现不另加 ID、重传、去重或重排。实际链路吞吐、丢包率及停止/软复位效果仍需板卡联调。

物理风速、中频偏移、三 ADC 的标定一致性和非等间距距离门映射待确认；这轮只输出三路原谱和小端 double 文件。
